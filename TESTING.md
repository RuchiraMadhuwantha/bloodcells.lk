# 3.2 Testing

Testing was carried out on the BloodCells.lk system using two complementary levels: **unit testing** of individual modules, services and utility functions, and **system testing** of the complete, running application (frontend + backend + database). The unit test results are generated by the automated Jest suite and cross-checked by a full re-run; the system test results were produced by manual end-to-end verification of the running system against the local MySQL database.

**Test environment**

| Item | Detail |
|---|---|
| Frontend | React 19 (react-scripts 5.0.1), served at `http://localhost:3000` |
| Backend | Node.js / Express API at `http://localhost:5000/api` |
| Database | MySQL (`nbts` schema, 12 tables) seeded with demo data |
| Unit test framework | Jest + React Testing Library via `react-scripts test` (`CI=true`) |
| System test method | Manual end-to-end browser verification + live API responses |
| Demo accounts | `demo_donor1`, `demo_hospital1`, `demo_bank` (role-matched) |

---

## 3.2.1 Unit Testing

Unit testing used Jest and React Testing Library to verify individual functions, services and React components in isolation, with the backend API mocked. A total of **123 unit tests across 17 suites** were executed. In one full parallel run, 5 tests in the navigation suites exceeded Jest's default 5-second timeout under parallel load; every affected suite was re-run individually and passed, confirming the failures were timing-related and not functional. The final verification state is **123/123 tests passing** across all 17 suites.
